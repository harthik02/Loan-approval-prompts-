==================================================
OBJECTIVE
==================================================

Build the Streamlit-based user interface that sits on top of
the existing Phase 6 REST API.

The architecture must be:

USER
 ↓
STREAMLIT UI
 ↓
PHASE 6 REST API
 ↓
EXISTING LANGGRAPH WORKFLOW
 ↓
EXISTING AGENTS
 ↓
MCP SERVERS / LLM
 ↓
LOAN DECISION
 ↓
REST API RESPONSE
 ↓
STREAMLIT UI

The UI must NOT directly implement loan approval/business logic.

The UI should communicate with the REST API.

==================================================
1. STREAMLIT APPLICATION
==================================================

Use the existing Streamlit dependency/infrastructure already present
in the project.

Create or complete the main Streamlit application using the existing
project structure.

The application should provide a professional academic demonstration
interface for the Agentic Loan Approval System.

==================================================
2. LOAN APPLICATION FORM
==================================================

Create a clear loan application form.

Collect the information required by the existing API.

Organize fields logically, for example:

Applicant Information
- Applicant name/identifier
- Age
- Employment information
- Income
- Employment stability
- Other existing applicant fields required by the API

Loan Information
- Loan amount
- Loan purpose
- Loan term
- Existing debt/financial information
- Any other fields required by the existing API

IMPORTANT:

Do NOT invent fields unnecessarily.

Inspect the existing API request models and database/application models
and use the fields that actually exist in the project.

Validate user input before submitting.

==================================================
3. SUBMISSION FLOW
==================================================

When the user clicks:

"Submit Loan Application"

the UI must:

1. Validate the form.
2. Send the request to the Phase 6 REST API.
3. Display an appropriate processing/loading state.
4. Receive the API response.
5. Display the loan decision clearly.

Do NOT call LangGraph directly from Streamlit.

Do NOT call agents directly from Streamlit.

Do NOT call MCP servers directly from Streamlit.

The API remains the application's backend entry point.

==================================================
4. DECISION DASHBOARD
==================================================

After receiving the response, display the result clearly.

The main decision should prominently show:

- APPROVED
- REJECTED
- MANUAL REVIEW

Also display the relevant information returned by the API, such as:

- Applicant/profile analysis
- Financial risk analysis
- Compliance result
- Risk information
- Decision reasoning/factors
- Application status
- Application ID

Only display information that actually exists in the API response.

Do not fabricate values.

==================================================
5. USER EXPERIENCE
==================================================

Make the UI clean and professional.

Use appropriate Streamlit components such as:

- forms
- columns
- expanders
- metrics
- status indicators
- tables
- progress/loading indicators

The application should look suitable for an academic project demonstration.

Keep the UI simple and understandable.

Do not over-engineer it.

==================================================
6. ERROR HANDLING
==================================================

Handle API failures gracefully.

Examples:

- API unavailable
- invalid request
- timeout
- server error
- workflow failure
- missing response fields

The user should receive a clear message such as:

"Unable to process the application. Please try again."

Do NOT expose:
- stack traces
- API keys
- credentials
- internal paths
- sensitive implementation details

Before implementing, inspect the Phase 6 API code and documentation
to determine the exact endpoint and payload structure.
